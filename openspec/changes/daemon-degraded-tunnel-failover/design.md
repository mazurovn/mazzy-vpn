# Design

## Context

Цикл health-check в `cmdDaemon` (`mazzy-vpn-cli/cmd/mazzy-vpn/daemon.go`): тикер 10 с, на каждом тике `lc.Check()` делает HTTPS-пробу egress (таймаут ~20 с, поэтому реальный период ≈ 30 с при потерях). Решение о реконнекте принимается по трём счётчикам: `fails` (жёсткие), `softFails` (при свежем handshake), `failoverLimit`. Источник возраста handshake — `conn.HandshakeAge()` через UAPI `last_handshake_time_sec`.

Ограничения: демон работает от root, тесты пакета `cmd/mazzy-vpn` не поднимают реальный туннель; логику нужно держать локальной и дешёвой (без новых горутин и зависимостей). Собирается с `-mod=vendor`.

## Goals / Non-Goals

**Goals:**
- Гарантированный выход из состояния «полудохлый туннель» за ограниченное время (≈ 1–2 мин).
- Нулевой риск reconnect-storm на здоровом туннеле (регрессия, которую когда-то чинили «свежим handshake»).
- Диагностируемость: в логе видны оба новых сигнала.

**Non-Goals:**
- Борьба с причиной потерь (DPI провайдера / throttling WG): это задача уровня AWG-параметров и выбора сервера, отдельное изменение.
- Изменение UI/дашборда, API, systemd-юнитов.

## Decisions

1. **Скользящее окно вместо порога «подряд».** `probeHist []bool` длиной 12; `noteProbe(ok) → lost`. Порог 5/12 (~40 %): здоровый туннель с редкими блокировками пробных URL не достигает его, флапающий с 50 % потерь — за ~10 тиков.
   Альтернатива — взвешенный счётчик (+2/−1): проще, но не отличает 33 % потерь от нуля. Отклонено.
2. **`softFails--` вместо `= 0`.** Минимальное изменение, сохраняет семантику лимита 6 для «подряд».
3. **Handshake churn через сравнение возрастов.** `noteHandshake(age)`: если возраст стал *меньше* предыдущего, а предыдущий был < 90 с → churn++; возраст ≥ 90 с → churn = 0. Не требует хранить абсолютный timestamp и устойчив к дрейфу часов.
   Порог 4 = ~2 мин при рекее каждые 30 с.
4. **Флаг `degraded` вместо `goto`.** На удачном тике ветка `s.Protected()` не делает `continue`, если сработал порог; выставляет `fails = reconnectLimit − 1` и подменяет `s.Reason`, после чего общий код реконнекта отрабатывает как для потери egress. `goto` в Go запрещён через объявления переменных, поэтому — флаг.
5. **Сброс всех накопителей** в точке `conn.Down()` реконнекта.

## Risks / Trade-offs

- Порог 5/12 подобран по одному инциденту; если у пользователя окажется зона с «нормальными» 30–40 % потерь проб, возможны лишние failover'ы. Смягчение: пороги — константы рядом, легко подстроить; лог печатает `window loss x/12` для калибровки.
- Churn-детектор опирается на поведение WG-рекея; при `PersistentKeepalive` < 30 с и здоровом сервере рекей всё равно раз в 2 мин, ложных срабатываний не ожидается.
- Проверка на реальном туннеле сегодня невозможна (пользователь на резервном AdGuard VPN); валидация — по логу после следующего подключения.
