# Повторный глубокий аудит Mazzy VPN — 2026-08-01

## Резюме

Повторный аудит восстановил точную причину отсутствия релиза: PR #32 оставался
draft и был заблокирован единственным Linux Desktop check из-за
`RUSTSEC-2024-0429` в `glib 0.18.5`. macOS, Windows, Bash regression tests и все
CodeQL jobs уже проходили. Опубликованными версиями оставались CLI/TUI 1.2.0 и
Desktop 0.2.0 preview.

Issue #31 исправлен в release candidate на уровне исходного кода, а не скрыт:

- зафиксирован оригинальный crates.io source `glib 0.18.5` с archive SHA-256
  `233daaf6e83ae6a12a52055f568f9d7cf4671dabb78ff9560ab6da230ce00ee5`;
- применён точный upstream fix gtk-rs
  `b5a4071e439bef2b5eea76c3aa25e5ae84839e34`: out-pointer стал mutable и
  передаётся как `&mut p`;
- `tests/check-glib-backport.py` сравнивает все файлы с исходным crate и
  допускает только эту двухстрочную дельту;
- Cargo graph использует локальный path override, поэтому registry-версия с
  unsound implementation отсутствует в release graph;
- cargo-deny проходит с пустым `ignore = []`.

Обновление RustSec-базы 1 августа дополнительно выявило
`RUSTSEC-2026-0221` в `event-listener 5.4.1` через `rfd`/`ashpd`. Lockfile
обновлён до исправленной версии 5.4.2; повторный cargo-deny завершился
`advisories ok`.

## Исправленные проблемы code review

### 1. Critical: незакрытый Linux RustSec release gate

Обычный semver update невозможен: Tauri 2.11.5 остаётся последним релизом,
архивированные GTK3 bindings остаются на `gtk 0.18.2`, а поддерживаемый glib
находится в несовместимой линии 0.20+. Maintainer gtk-rs 31 июля 2026 года
подтвердил, что новых релизов ветки 0.18 не будет. Минимальный backport выбран
потому, что он не меняет Rust API или native GLib ABI и побайтово совпадает с
уже принятым upstream исправлением.

### 2. High: новый RustSec advisory в `event-listener`

Предыдущий аудит использовал более старую advisory database. Текущая база
нашла безопасно обновляемый transitive package. Это подтверждает, что release
gate должен получать свежую базу на каждом CI/release run, а не полагаться на
результат предыдущей даты.

### 3. High: возможное зависание Desktop на унаследованном pipe

Rust adapter запускал helpers через GNU `timeout --foreground`, затем ждал
reader threads stdout/stderr. Если timed-out process оставлял потомка с
унаследованными file descriptors, `timeout` мог завершиться, а reader thread —
остаться заблокированным. `--foreground` удалён из Desktop helpers, чтобы
timeout управлял отдельной process group. Regression test создаёт shell с
background `sleep`, удерживающим pipes, и требует завершения менее чем за пять
секунд.

### 4. Medium: дублированный privileged path в tray

`main.rs` содержал отдельную таблицу CLI-аргументов и прямой `pkexec` adapter,
хотя все доступные tray actions уже проходили через typed backend или
структурированные probe/verify adapters. Недостижимый fallback удалён. Теперь
window и tray используют одну allowlisted модель операций, одинаковые
deadlines, sanitization, local API retry/idempotency и compatibility fallback.

### 5. High: неполный corresponding-source payload после path override

Первый вариант backport добавлял `vendor/glib-0.18.5` в Cargo graph, но package
resource map ещё не включал этот каталог. Готовый binary был бы рабочим, однако
вложенный source snapshot не позволял бы воспроизвести сборку и проверить
remediation. AppImage/DEB/RPM теперь включают vendor, `deny.toml`, pinned Rust
toolchain и provenance verifier; package audit требует эти файлы и побайтово
сравнивает patched implementation со source tree.

## Архитектурная оценка

### Сильные стороны

- WebView не получает profile contents, endpoints, credentials или произвольные
  пути; Rust десериализует status/profile/probe/egress в строгие структуры с
  `deny_unknown_fields` и проверяет cross-field invariants.
- Мутации local API имеют opaque action ID, deadline, durable audit,
  serialization, rollback и same-action retry после потерянного ответа.
- CLI/TUI/Desktop уже используют общий v1 API для status, profiles, lifecycle и
  batch probe; indeterminate mutation не повторяется через другой privilege
  path.
- Bash engine покрыт 74 end-to-end regression tests, включая rollback,
  watchdog, boot recovery, spoofing, API memory/deadline bounds и package
  lifecycle.
- Release scripts имеют фиксированный command surface; package audit сверяет
  assembled engine/API/source с repository content.

### Оставшиеся архитектурные риски

- `mazzy-vpn` остаётся монолитным Bash-файлом примерно на 7.5 тыс. строк,
  `backend.rs` — примерно 2.7 тыс., `app.js` — примерно 1.5 тыс. Это повышает
  стоимость review и вероятность междоменного regression. Разделение должно
  идти по API domains после релиза, без большого предрелизного rewrite.
- Local API остаётся partial: live tests, services, Doctor и settings ещё идут
  через typed `pkexec` compatibility adapter. Это честно отмечено в schema и
  capability matrix.
- Unix socket защищён filesystem permissions/systemd policy, но Rust client не
  подтверждает peer credentials через `SO_PEERCRED`. Для production shared
  service это отдельный hardening gate.
- Linux Desktop 0.3 остаётся preview: нет подписанных artifacts,
  attestations/SBOM, полной clean-device distro matrix, rollback/fault/soak и
  сложной legacy migration.
- macOS и Windows packages остаются UI previews без native VPN backend;
  Android/iOS отсутствуют. Их нельзя включать в утверждение о production
  cross-platform VPN.

## Почему релиза ещё нет и порядок выпуска

Source remediation готов, но GitHub release нельзя считать существующим до
полного внешнего цикла:

1. зафиксировать и push изменения в PR #32;
2. получить зелёные Linux/macOS/Windows Desktop, CI и CodeQL checks;
3. merge в `main` и дождаться default-branch Dependabot scan, который должен
   автоматически закрыть registry alert для `glib 0.18.5`;
4. закрыть issue #31 только после подтверждения graph/alert;
5. создать и опубликовать CLI/TUI tag/release `v1.3.0`;
6. создать `desktop-v0.3.0`, дождаться audited matrix artifacts и опубликовать
   их как **preview**, не как Desktop 1.0 production.

Открытые issues #4–#14 не являются обещанием включить Android, iOS, native
Windows/macOS backend или все Desktop 1.0 gates в релиз 0.3. Они остаются
следующими roadmap slices и не должны маскироваться release notes.
