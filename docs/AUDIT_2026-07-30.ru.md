production release. CLI/TUI tests, Desktop macOS/Windows validate, CodeQL и
локальная Linux сборка проходят. Linux Desktop publication всё ещё должна быть
заблокирована: Ubuntu Desktop validate падает на `cargo-deny` из-за
`glib 0.18.5` / `RUSTSEC-2024-0429`, который приходит через текущий Tauri/GTK3

Этот блокер нельзя закрывать `ignore` в `deny.toml`: Mazzy VPN напрямую не
вызывает проблемный `glib::VariantStrIter`, но это не доказывает недостижимость
через `gtk`, `tray-icon`, `webkit2gtk`, `wry` или Tauri runtime. Production fix
должен убрать или патчить affected implementation в итоговом Linux dependency
graph.

## Архитектурный review

### Privilege boundary

Сильные стороны:

- WebView не строит shell-команды. Все операции идут через Tauri commands и
  Rust enum `OperationRequest`.
- CLI arguments строятся allowlist-логикой: protocol, timeout, language,
  profile names и import paths валидируются до запуска процесса.
- Lifecycle operations (`connect`, `reconnect`, `disconnect`) сначала идут в
  protected local API с opaque `profile_id`; при indeterminate ответе Desktop
  не делает небезопасный fallback через `pkexec`.
- Status/profile/probe/egress JSON перед WebView строго десериализуются в Rust
  типы с `deny_unknown_fields` и cross-field invariants.

Оставшиеся проблемы:

- Большинство non-lifecycle operation domains ещё используют typed `pkexec`
  adapter. Это лучше произвольного shell, но хуже единого daemon API с
  action-id, peer identity и reconciliation.
- Unix socket policy ограничена группой, но Bash dispatcher не получает
  `SO_PEERCRED`; audit не доказывает UID/PID caller.
- Идемпотентность bounded journal конечна: очень старый `action_id` после
  prune теоретически может повториться. Нужен server-issued token/expiry или
  другой протокол, а не бесконечный локальный журнал.

### Desktop/WebView logic

Сильные стороны:

- UI использует `textContent`, а contract test запрещает `innerHTML`,
  `insertAdjacentHTML`, `eval` и `new Function`.
- Documentation preview отделён от packaged runtime и допускается только в
  local HTTP browser mode.
- Privacy mode скрывает IP по умолчанию.
- Active profile state резолвится через `profile_id`/`profile_file_name`, а не
  только через display name.

Оставшиеся проблемы:

- macOS/Windows validate доказывают сборку UI, но не functional VPN backend.
  Эти artifacts нельзя называть рабочим VPN.
- Fallback-policy UI и полная миграция всех controls на versioned local API
  остаются gate Desktop 1.0.

### Release and CI

Сильные стороны:

- OS runner labels и Rust toolchain закреплены.
- `build-release.mjs` игнорирует caller args, чистит старые bundles и
  пересобирает release artifacts.
- `tauri-audited.mjs` добавляет Linux package audit после bundle build.
- `deny.toml` не содержит advisory ignores; `unused-ignored-advisory = "deny"`.

Оставшиеся проблемы:

- Production release chain всё ещё не доверенная: unsigned artifacts, нет
  provenance/SBOM/signing gate.
- Ubuntu Desktop CI intentionally red из-за `glib` RustSec. Это правильное
  fail-closed состояние до upstream migration/backport.

## Code review findings

1. **Release blocker: `glib 0.18.5` unsound advisory.**
   Файл: `desktop/src-tauri/Cargo.lock`.
   Лог CI показывает `RUSTSEC-2024-0429`, solution `glib >=0.20.0`, dependency
   path через `gtk 0.18.2`, `tray-icon`, `tauri`, `webkit2gtk`, `wry`.
   Это не исправляется безопасным direct override, потому что GTK3 bindings
   ABI/API graph остаётся на серии 0.18.

2. **Architectural blocker: partial local API.**
   Файлы: `mazzy-vpn`, `desktop/src-tauri/src/backend.rs`.
   Lifecycle уже защищён лучше, но import/test/doctor/service controls всё ещё
   совместимостно запускаются через `pkexec`. До Desktop 1.0 нужен единый
   native service/API boundary.

3. **Platform blocker: non-Linux backends absent.**
   Файлы: `docs/capabilities.json`, `docs/FEATURE_PARITY.md`,
   `desktop/src-tauri/src/main.rs`.
   macOS/Windows Desktop validate green означает build health, а не VPN traffic
   protection.

4. **Fixed: batch API lock FD lifetime.**
   Файл: `mazzy-vpn`.
   `api_probe_result` и `api_verify_result` больше не оставляют lock lifetime
   на глобальном `exec 8>`; lock FD scoped редиректом command group.

5. **Fixed: tray output sanitizer drift.**
   Файлы: `desktop/src-tauri/src/main.rs`,
   `desktop/src-tauri/src/backend.rs`.
   Tray events теперь используют тот же bounded/sanitized output path, что и
   обычные operations.

## Следующий порядок работ

1. Закрыть issue #31 без `cargo-deny ignore`: upstream Tauri/GTK migration,
   reviewed backport или смена Linux Desktop stack.
2. Перенести оставшиеся mutation/read operation domains с `pkexec` adapter на
   protected daemon API с peer credentials.
3. Добавить clean-device Linux gate: fresh install, upgrade, uninstall,
   reboot/crash recovery, route/DNS/IPv6 leak checks.
4. Только после зелёного Linux RustSec gate публиковать Desktop 0.3 preview
   artifacts; production 1.0 требует signing/provenance и native platform
   backends.
