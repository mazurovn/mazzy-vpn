# ADR-0005: Как movzy-core общается с ядром (routes/dns/nft)

- Статус: **ПРИНЯТО** (с планом усиления)
- Дата: 2026-08
- Связано: ADR-0003 (автономность), аудит R1.

## Проблема

`amneziawg-go` даёт крипто+TUN, но НЕ настраивает адреса интерфейса, маршруты,
policy-routing (fwmark), DNS и kill-switch (nftables). Это наш код. Вопрос: как
именно применять сетевые изменения?

## Варианты

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Native netlink (pure Go) | максимум автономности, нет внешних процессов | нужен netlink-стек; nftables через netlink очень сложен; +крупная Go-зависимость |
| B. Exec базовых утилит `ip`/`nft`/`resolvectl` | паритет с wg-quick 1:1, малый код, предсказуемость | зависит от `ip`/`nft` (base iproute2/nftables) |

## Различение «зависимости»

Требование заказчика — «не устанавливать библиотеки, быть самодостаточным».
Разделяем, как и для Desktop (ADR-0004):

- **Устанавливаемые VPN-зависимости** (`awg`, `awg-quick`, `openvpn`, `jq`,
  `socat`, `amneziawg-go`-сборка) — **запрещены**. Их убираем.
- **Базовые системные утилиты ядра** (`ip` из iproute2, `nft` из nftables) —
  присутствуют на любом Linux с сетью, это часть ОС, а не «библиотека для
  установки». Их использование НЕ нарушает требование.

## Решение

**Этап 1: Вариант B** — routes/dns/guard выполняют `ip`/`nft`/`resolvectl`
через `os/exec` со **строгой сборкой аргументов** (без shell, без интерполяции),
сохраняя паритет с wg-quick.

Обоснование:
1. Паритет с проверенной логикой wg-quick 1:1 — минимальный риск для
   безопасности (kill-switch, fwmark, suppress_prefixlength).
2. Малый объём кода, легко аудировать.
3. `ip`/`nft` — базовые, уже требуются и проверяются doctor.

**Этап 2 (усиление, backlog): Вариант A** — перевести маршруты и адреса на
native netlink (`golang.org/x/sys/unix` или vendored netlink-пакет), оставив
`nft` для kill-switch. Даст ещё большую автономность.

## Инварианты (обязательны в реализации B)

- Никакого `sh -c`/строковой интерполяции — только `exec.Command(bin, args...)`.
- Все имена интерфейсов/таблиц/адресов валидируются перед передачей.
- Полный симметричный teardown (down снимает всё, что поставил up).
- Fail-closed: при ошибке настройки — не оставлять полуоткрытое состояние.

## Последствия

- `core/routes`, `core/dns`, `core/guard` инкапсулируют exec; остальной код
  их не видит.
- Doctor продолжает проверять наличие `ip`/`nft`/`resolvectl` (это ОС, не VPN).
- Техдолг: native-netlink помечен задачей C1-4d.
