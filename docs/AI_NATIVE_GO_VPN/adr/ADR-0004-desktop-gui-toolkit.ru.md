# ADR-0004: GUI-тулкит для Desktop (Go)

- Статус: **ПРИНЯТО** (финализировано в Раунде 3, критерий — самодостаточность)
- Дата: 2026-08
- Связано: ADR-0002 (автономность продуктов), правило «ноль установки библиотек».

## Проблема

Текущий Desktop на Tauri (Rust + webview) заказчика не устраивает по работе.
Требование заказчика жёсткое: **клиент самодостаточен, ничего дополнительно не
устанавливаем, не зависим от библиотек**.

## Решающий критерий: что нужно ДОУСТАНАВЛИВАТЬ пользователю

Разделяем два класса зависимостей:

- **Базовая графика ОС** (X11/Wayland/OpenGL/EGL/xkbcommon) — присутствует на
  любом Linux-десктопе по определению. Опираться на неё — НЕ нарушение
  самодостаточности: это часть графической системы, а не «библиотека, которую
  надо ставить».
- **Тяжёлый рантайм-фреймворк** (webkit2gtk/GTK, .NET, Electron) — это то, что
  пользователь **вынужден доустанавливать**. Именно это нарушает требование.

### Факты (проверено на целевой системе)

| Компонент | Наличие по умолчанию |
|---|---|
| `libGL.so.1`, `libEGL.so.1` | есть |
| `libX11.so.6`, `libwayland-client.so.0` | есть |
| `libxkbcommon.so.0`, `libvulkan.so.1` | есть |
| `libwebkit2gtk-4.1` | есть здесь, но **тяжёлая внешняя зависимость** в DEB |

Сессия: Wayland (`XDG_SESSION_TYPE=wayland`).

## Сравнение под критерием самодостаточности

| Тулкит | Что тянет пользователю | Самодостаточность |
|---|---|---|
| **gio** | только базовая графика ОС (X11/Wayland/GL/EGL/xkbcommon) | ✅ **максимальная**; ни webkit, ни GTK-рантайма |
| Fyne | базовая графика ОС + GL | ✅ высокая; но свой look, тяжелее |
| Wails | **webkit2gtk/GTK** — тяжёлый webview-рантайм | ❌ нарушает «ничего не доустанавливать» |
| Tauri (текущий) | **webkit2gtk** | ❌ то, чем недоволен заказчик |

## Решение

**Desktop реализуется на `gioui` (gio).**

Обоснование:

1. **Единственный вариант без внешнего webview/GTK-рантайма.** gio рисует через
   OpenGL/Vulkan/EGL поверх базовой графики ОС, которая и так есть. Пользователь
   **ничего не доустанавливает** — ровно требование заказчика.
2. **Чистый Go, один статический бинарник.** Линкует общий `core/` (`mazzy-core`)
   напрямую → Desktop работает **без CLI** (ADR-0002).
3. **Убирает webkit2gtk** — источник недовольства текущим Tauri.
4. Кроссплатформенность gio (Linux/Windows/macOS) — задел на будущее.

## Отклонённые варианты

- **Wails** — отклонён: зависит от системного webkit2gtk/WebView2, что и есть
  «библиотека, которую надо ставить». Прямо противоречит требованию.
- **Fyne** — приемлем по самодостаточности, но тяжелее и с собственным look;
  gio даёт больше контроля и меньший рантайм.

## Последствия и риски

- **UX пишем с нуля** на gio (immediate-mode): нельзя переиспользовать текущий
  web-фронт `static/`. Это осознанная цена самодостаточности.
- **Сборка требует cgo + dev-заголовки** X11/Wayland/GL/xkbcommon (проверено:
  присутствуют). Это зависимость **сборочной машины**, не конечного
  пользователя — бинарник линкует системные `.so`, которые есть везде.
- Трей-иконка и автозапуск: gio сам трей не даёт — используем отдельный
  чистый-Go пакет для трея или минимальную нативную интеграцию (задача Фазы 3).
- Проверить рендеринг на Wayland и X11 на целевых DE (задача Фазы 3).

## Критерий приёмки

- Desktop-бинарник запускается на чистом Linux-десктопе **без установки**
  webkit/GTK/Electron/.NET.
- Подключение к VPN работает **без установленного CLI** (общий `core/`).
