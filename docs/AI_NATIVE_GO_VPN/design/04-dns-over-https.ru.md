# Design + Audit — Задача 3: DNS-over-HTTPS через VPN-страну

Роль: designer + auditor. Задача: убрать DNS-утечку, резолвить из VPN-страны.

## Аудит текущего состояния

Профиль содержит `DNS = 1.1.1.1`. Наш `core/dns` применяет его через
`resolvectl dns vpnaw0 1.1.1.1`. DNS-запросы идут **через тоннель** (bound к
vpnaw0), поэтому выходят из VPN-egress.

**Проверка вживую:** `1.1.1.1/cdn-cgi/trace` → `loc=NL` — DNS уже резолвится из
Нидерландов. Утечки НЕТ на уровне маршрута.

## Критический анализ

### Что уже хорошо
- DNS bound к tunnel-интерфейсу → запросы шифруются и выходят из VPN-страны.
- `resolvectl` изолирует DNS per-interface (не течёт в системный резолвер).

### Остаточные риски
1. **Plain DNS (порт 53)** виден на VPN-сервере (не зашифрован внутри тоннеля к
   резолверу). Провайдер VPN-сервера может логировать.
2. **Split-DNS**: если приложение использует свой резолвер (не системный) —
   может течь мимо. Редко, но возможно.
3. **DNSSEC/ECS**: EDNS Client Subnet может раскрывать подсеть.

### Нужен ли DoH?
DoH (DNS-over-HTTPS) шифрует DNS **до резолвера**, скрывая запросы даже от
VPN-сервера, и использует HTTPS (порт 443, неотличим от обычного трафика).
Это усиление приватности, но:
- добавляет зависимость (DoH-клиент);
- `resolvectl` умеет DoH нативно (`resolvectl dns -4 vpnaw0 1.1.1.1#cloudflare-dns.com`)
  на новых systemd — **проверить поддержку**.

## Дизайн-решение

**Двухуровневый:**

1. **Анализ (`dns-check`):** новая команда проверяет:
   - через какую страну резолвится DNS (совпадает с egress?);
   - используется ли DoH/DoT (шифрование до резолвера);
   - нет ли утечки в системный резолвер.
   Даёт verdict + рекомендации.

2. **DoH-опция (`dns --doh`):** если systemd-resolved поддерживает DoT,
   включить шифрование DNS до резолвера через VPN-страну. Иначе — рекомендация.

## Компоненты

| Что | Где |
|---|---|
| `DNSAnalysis{egressCC, dnsCC, encrypted, leak}` | core/dnscheck |
| Проверка DoT-поддержки resolvectl | core/dnscheck |
| CLI `dns-check` | CLI |
| Рекомендация настройки DoH | CLI |

## Аудит рисков

| Риск | Ответ |
|---|---|
| DoH-провайдер сам логирует | выбор in-country резолвера; честно предупредить |
| resolvectl без DoT-поддержки | fallback на plain-in-tunnel (уже безопасно по маршруту) |
| Ломается резолв при неверном DoH | dry-run + verify перед применением |

## Вердикт

Маршрутная утечка уже закрыта (DNS через тоннель, loc=NL). Добавляем `dns-check`
(анализ страны/шифрования/утечки) как основную ценность, и опциональный DoT
через resolvectl где поддерживается. Не переусложняем — фокус на проверках.
