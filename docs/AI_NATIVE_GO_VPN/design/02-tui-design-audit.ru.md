# Design Audit — Mazzy VPN TUI redesign (top-model review)

Роль: design auditor (fresh-context critical review). Оцениваю designer-spec
(`01-tui-designer-pass.ru.md`) по usability, иерархии, доступности, failure
states и рискам реализации.

## Вердикт: спецификация сильная, но 6 проблем требуют правки до кода

## Найденные проблемы

### D1 — P1 — bubbletea тянет зависимости, конфликт с «автономностью»
Проект — про автономность и минимум зависимостей (ADR-0003). bubbletea +
lipgloss + bubbles = 3 новых модуля + их транзитивные (~15 пакетов). Это надо
**vendored** и проверить лицензии (MIT — ок), но размер vendor вырастет.

**Рекомендация:** принять осознанно (UI-качество того стоит), но зафиксировать
в ADR: bubbletea vendored, статическая сборка сохраняется (`CGO_ENABLED=0`).
Проверить, что bubbletea не тянет cgo (не тянет — чистый Go). **Блокер до
кода: подтвердить static build с bubbletea.**

### D2 — P1 — root-привилегии в интерактивном TUI
Connect/disconnect/recover требуют root. Если TUI запущен под sudo — весь UI
под root (небезопасно, файлы настроек станут root-owned). Если без root —
hotkey `[c]` не сможет поднять тоннель.

**Рекомендация:** TUI работает **без root**; привилегированные действия
делегируются: TUI пишет намерение и показывает `sudo mazzy-vpn up …` ИЛИ
использует уже-запущенный `daemon` (TUI — только монитор+управление через
state). Лучший вариант: **TUI управляет daemon'ом** (start/stop/switch zone
через сигнал/файл), а daemon под systemd держит root. Это чистое разделение.

### D3 — P2 — «Activity log» без ограничения = утечка памяти
Прокручиваемая лента событий за долгую сессию растёт неограниченно.

**Рекомендация:** кольцевой буфер (последние 200 строк), viewport показывает
хвост.

### D4 — P2 — конфликт hotkeys с bubbles list-навигацией
`[c][z][d]…` — буквы, но bubbles `list` использует буквы для фильтрации/поиска.
Пересечение сломает ввод в overlay со списком зон.

**Рекомендация:** глобальные hotkeys активны только на главном экране; в
overlay (список зон) — навигация стрелками + Enter, буквы = фильтр. Явно
разделить контексты ввода (focus state в Model).

### D5 — P2 — спиннер «connecting…» без таймаута = вечное ожидание
Если connect висит (мёртвый сервер), спиннер крутится бесконечно.

**Рекомендация:** каждая async-команда с deadline (connect 20s, test 90s),
по таймауту → failure-state в header + запись в log. Уже есть в
`livecheck.WaitProtected` — переиспользовать.

### D6 — P3 — эмодзи-ширина в lipgloss
Эмодзи (⚡🌍🩺) имеют неоднозначную ширину в терминалах; рамки поедут даже с
lipgloss на некоторых эмуляторах.

**Рекомендация:** для рамок/выравнивания использовать ASCII-символы статуса
(●▲✖◐⟳), эмодзи — только в неструктурных подписях действий (где перенос не
ломает layout). Протестировать на 2-3 терминалах.

## Что в спецификации хорошо (подтверждено)

- Разделение зон (header/action/log/overlay) — правильная Elm-структура.
- Non-blocking через tea.Cmd — решает P3 текущего TUI.
- Failure-states таблица — покрывает реальные состояния (это редко делают).
- Fallback `--plain` для не-TTY — важно для скриптов/пайпов.
- Дублирование статуса символом (доступность без цвета) — верно.

## Приоритеты реализации (по итогам аудита)

| Порядок | Что | Причина |
|---|---|---|
| 1 | Подтвердить static build с bubbletea (D1) | блокер |
| 2 | Решить модель привилегий: TUI↔daemon (D2) | архитектурный блокер |
| 3 | Кольцевой буфер лога (D3) | стабильность |
| 4 | Контексты ввода main/overlay (D4) | корректность |
| 5 | Таймауты async-команд (D5) | UX |
| 6 | ASCII для layout, эмодзи в подписях (D6) | визуал |

## Рекомендация консилиума

Спецификация **принята с правками D1-D6**. Ключевые архитектурные решения до
кода: (D1) vendored bubbletea + static build, (D2) TUI как контроллер daemon'а,
а не sudo-обёртка. Остальное — детали реализации.

## Граница честности

Это review одной моделью (текущий агент) с design-экспертизой, не многомодельный
консилиум. Для финального UX-решения (особенно D2 — модель привилегий) полезен
второй независимый проход другой топ-модели через локальный Control Panel, когда
доступен pi-subagents runtime. Задача зафиксирована в backlog
(id 1a09f53d) для такого прохода.
