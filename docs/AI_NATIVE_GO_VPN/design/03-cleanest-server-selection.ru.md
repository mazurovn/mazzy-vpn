# Design + Audit — Задача 1: подбор наименее flagged сервера

Роль: designer + auditor. Задача: авто-подбор сервера, который меньше палится
как VPN (residential vs datacenter ASN).

## Аудит текущего состояния

`measure.RankBest` сортирует по: ICMP-живость → латентность. НЕ учитывает,
как egress выглядит для сервисов (proxy/hosting ASN).

## Критический анализ (что реально важно)

### Ошибка наивного подхода
Проверять ASN **endpoint'а** VPN-сервера (IP из конфига) — БЕСПОЛЕЗНО:
- endpoint — это адрес, куда мы шлём зашифрованный трафик;
- сервисы видят **egress-IP** (адрес, с которого сервер выходит в интернет);
- endpoint и egress часто РАЗНЫЕ IP (и разные ASN).

Пример из реальных данных: endpoint AustriaGrazS6 = `151.236.2.119`, а egress
после подключения = `151.236.9.205` — разные адреса.

### Правильный подход
ASN/proxy-флаг egress можно узнать ТОЛЬКО после подключения (через `stealth`).
Поэтому «наименее flagged сервер» нельзя определить заранее по конфигу.

## Дизайн-решение

**Двухфазный подбор с кэшем результатов:**

1. **Быстрая фаза (без подключения):** ранжирование по ICMP-живости+латентности
   (как сейчас) — выбор кандидатов.
2. **Оценочная фаза (после подключения):** `stealth` измеряет egress-ASN
   (proxy/hosting флаг) и **кэширует** score per-zone в
   `~/.config/mazzy-vpn/zone-scores.json`.
3. **Умный выбор:** `up --clean` предпочитает зоны с лучшим **закэшированным**
   stealth-score; если кэша нет — берёт лучшую живую и оценивает по факту.

### Почему кэш
Проверять egress-ASN каждой зоны = подключаться к каждой (дорого). Кэш
накапливает оценки по мере использования: со временем система знает, какие
зоны «чище».

## Компоненты

| Что | Где |
|---|---|
| `ZoneScore{name, stealthScore, isDatacenter, egressCC, ts}` | core/zonescore |
| Кэш load/save (per-user JSON) | core/zonescore |
| `up --clean` — выбор по кэшу | CLI |
| После connect: записать score в кэш | CLI (auto) |

## Аудит рисков

| Риск | Ответ |
|---|---|
| ASN-API rate-limit | оцениваем только текущий egress (1 запрос на connect), кэшируем |
| Кэш устаревает | timestamp + TTL (сервер мог сменить ASN); refresh по возрасту |
| Нет кэша при первом запуске | fallback на ICMP-ранжирование (текущее поведение) |
| datacenter неизбежен для VPN | честно: снижаем penalty, не блокируем; residential редки |

## Вердикт

Наивный «ASN endpoint» отвергнут (неверный сигнал). Принят двухфазный подход
с кэшем egress-оценок. Реализуем `core/zonescore` + `up --clean` + авто-запись
score после подключения.
