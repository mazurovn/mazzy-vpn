# Двухплоскостная AI-native маршрутизация (реализация)

Статус: реализовано в Go. Дата: 2026-08.

## Две плоскости в коде

```
┌── Плоскость 1: CONTROL (core/control) ──────────────────────┐
│  Кто может подключиться к агенту ИЗВНЕ                        │
│  Участники: agent, harness, user, app, peer                  │
│  Deny-by-default маршруты (Allow/Revoke), направленные       │
│  CanReach(from,to) — единственный путь доступа               │
└──────────────────────────────────────────────────────────────┘
┌── Плоскость 2: PROVIDER (core/provider) ────────────────────┐
│  Агент → провайдер/LLM, надёжно ОБХОДЯ блокировки            │
│  CheckRegion: egress-страна поддержана И согласована с       │
│  таймзоной И (опц.) с target → Ready, иначе NotReady         │
│  Ловит: unsupported-country, egress/timezone-mismatch        │
└──────────────────────────────────────────────────────────────┘
```

## Плоскость 1 — control (подключение агентов извне)

`core/control.Plane` — реестр участников + направленные авторизации.

- **Deny-by-default:** без явного `Allow(from,to)` доступа нет. Это
  единственный путь к `CanReach=true`. Проверено `TestDenyByDefault`.
- Направленность: `Allow(h,a)` не даёт `a→h`.
- `Deregister` чистит все маршруты к/от участника (нет висячих прав).
- Потокобезопасно (RWMutex), `-race` чист, 100% покрытие.

## Плоскость 2 — provider (агент → LLM без блокировок)

`core/provider.CheckRegion` — решает, безопасно ли агенту опираться на текущий
выход при работе с LLM. Провайдер, который геоблокирует или челленджит
несогласованный регион, рвёт длинные сессии агента, поэтому проверяем ДО.

Verdict `Ready` требует ВСЕ условия:
1. egress-страна в `SupportedCountries` провайдера;
2. egress-страна == страна системной таймзоны (иначе — классический триггер
   VPN-детекта);
3. если задан target — egress и таймзона совпадают с ним.

Иначе `NotReady` с конкретными `mismatches` (машиночитаемо для агента, чтобы
он выбрал другой выход). Паритет с bash `region_check_json`.

## Как это «AI-native»

- Агент программно спрашивает: «могу ли я сейчас надёжно достучаться до OpenAI
  из этого выхода?» → структурированный verdict + причины.
- Харнесс извне авторизуется к агенту через deny-by-default control plane.
- Обе плоскости — чистая политика/логика, транспорт даёт data plane
  (engine/routes/guard), что уже автономно.

## Интеграция

`TestScenarioAINativeTwoPlanes` связывает обе: harness→agent (Plane 1, deny→allow)
и egress-region-check для LLM (Plane 2, ready/blocked).
