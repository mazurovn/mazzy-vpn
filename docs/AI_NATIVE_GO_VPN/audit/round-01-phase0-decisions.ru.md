## 2. НАЙДЕННЫЕ ДЕФЕКТЫ / РИСКИ (то, что ADR недооценивали)

### R1 — P0 — «amneziawg-go заменяет awg-quick» НЕВЕРНО по объёму работы
**Факт:** `IpcSet()` принимает только UAPI-уровень: `private_key`,
`listen_port`, `public_key`, `endpoint`, `allowed_ip`, `preshared_key` и
Amnezia-параметры. Он **НЕ** настраивает: адрес интерфейса (`Address =`),
маршруты, `ip rule`/fwmark, DNS, MTU. В `wg-quick/linux.bash` — **41** место
с `ip route`/`ip rule`/`resolvconf`/`fwmark`/`nft`.

**Вывод:** `amneziawg-go` даёт только крипто-движок и TUN-обмен. Вся
«обвязка» wg-quick (routes/DNS/policy-routing/kill-switch) — это **наш код**,
которого нет в vendored-библиотеке. ADR-0003 это подразумевал модулями
`tun/routes/dns/nft`, но бэклог C1-4 недооценивает объём: это порт ~41
операции wg-quick + текущая transition-guard логика.

**Правка:** C1-4 повысить оценку; выделить `routes`, `dns`, `policyrouting`,
`mtu` как отдельные задачи с тестами против поведения wg-quick.

### R2 — P0 — Кто парсит `.conf`? В `amneziawg-go` парсера нет
**Факт:** grep по `[Interface]`/`[Peer]`/`Address =` в `amneziawg-go` —
**пусто**. Формат wg-quick `.conf` парсит `amneziawg-tools` (C-код), которого
мы НЕ вендорим. `IpcSet` ест UAPI, а не `.conf`.

**Вывод:** нужен **собственный Go-парсер** wg-quick-конфига → UAPI + извлечение
Address/DNS/MTU для обвязки. Это отсутствовало явной задачей.

**Правка:** добавить задачу **C1-6a — Go-парсер AmneziaWG/WG `.conf`** (P0),
включая Amnezia-поля (Jc/Jmin/Jmax/S1/S2/H1..H4).

### R3 — P1 — Go toolchain mismatch (реальный блокер сборки)
**Факт:** `amneziawg-go/v3` требует `go 1.25.0`; Android-движок — `go 1.25.0`.
`go` на PATH по умолчанию — **1.22.10** (слишком старый). Но `/usr/local/go` =
**1.25.5** (подходит), `GOTOOLCHAIN=auto`.

**Вывод:** сборка сломается «молча» при использовании PATH-`go`. Нужно
зафиксировать toolchain.

**Правка:** добавить `go.mod` с `go 1.25.x` + CI/скрипт, пинящий
`/usr/local/go` или `GOTOOLCHAIN=go1.25.x`. Задача **C1-1a — pin toolchain**.

### R4 — P1 — «Desktop полностью автономен от системного webview» под вопросом
ADR-0004: Wails зависит от системного WebKitGTK/WebView2. Требование «автономен
от библиотек» тогда выполняет только **gio** (чистый Go, без webview). Это
усиливает предварительную рекомендацию gio, но ценой переписывания UX. Решение —
на Раунд 3.

### R5 — P2 — OpenVPN «vendored статик» ≠ «автономно от библиотек» строго
Vendored статический бинарник OpenVPN — это внешний процесс внутри пакета, а не
Go-native код. Формально нарушает дух «всё внутри своего кода», хотя
удовлетворяет «без установки зависимостей». Зафиксировать как осознанный
компромисс этапа 1 (уже отмечено в ADR-0003), но пометить как **техдолг**.

### R6 — P2 — Слой 1 (control plane) почти не специфицирован
Концепция описывает участников (агенты/харнессы/устройства), но нет протокола
идентификации, доверия и авторизации связей «кто с кем». Для AI-native это
центральная часть, а в бэклоге она — Фаза 4 (P1/P2). Риск: data plane сделаем,
а ради чего (Слой 1) — недоспроектировано.

**Правка:** добавить SDD-документ по контракту Control Plane до Фазы 4.

## 3. Подтверждённые сильные решения

- Go + vendored amneziawg-go как путь «без FFI + автономно» — **подтверждён**
  на уровне API (библиотека реальна, обфускация доступна, лицензия совместима).
- Разделение на три продукта на общем `core/` — архитектурно корректно.
- Инварианты безопасности из bash перечислены и подлежат переносу.

## 5. Вердикт раунда

Решения Фазы 0 (Go, три продукта, автономный движок) **подтверждены по
существу**, но **два P0-уточнения обязательны до старта кода**: (R1) объём
обвязки wg-quick и (R2) собственный парсер `.conf`. Без них C1 недооценён и
рискует «зелёным движком без маршрутов».

## 6. Что осталось для полного консилиума (честная граница)

Данный раунд — review с верификацией на коде, но **не** многоагентный
fresh-context консилиум (несколько независимых моделей). Для P0-подтверждения
перед Фазой 2 нужен полноценный консилиум через локальный Control Panel
(`tools/mazzy-control-panel/`), как в `MAZZY_CONTROL_PANEL_AUDIT_2026-08-16`.
Отмечено задачей F0-6b.
