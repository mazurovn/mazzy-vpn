## Вердикт

Текущий `main` нельзя считать готовым к production-релизу Desktop или mobile.
CLI/TUI 1.2.0 остаётся единственным стабильным релизом, но защищённый local API
и его клиенты находятся в Draft PR
[#26](https://github.com/mazurovn/mazzy-vpn/pull/26) и
[#27](https://github.com/mazurovn/mazzy-vpn/pull/27), а не в `main`.

Linux Desktop 0.2.0 — preview. Windows и macOS артефакты — неподписанные UI
preview без VPN backend. Исходников Android/iOS приложений в репозитории нет.
Выпускать эти четыре платформы как работающий VPN сейчас нельзя.

Аудит охватывает Bash engine/installer, systemd local API, CLI/TUI, Rust/Tauri
Desktop adapter, GitHub Actions, release artifacts, dependency chain,
capability registry и планы Windows, macOS, Android и iOS.

## Незакрытые технические риски

### P0 — блокируют production

1. **Нет общего native core/service.** `mazzy-vpn` — root-executed Bash-монолит
   более чем на 5 500 строк. Local API реализует только status, profiles и
   lifecycle на Linux; остальные Desktop операции продолжают использовать
   `pkexec`. Это не переносимая архитектура Windows/macOS/mobile.
2. **Нет идентификации вызывающего процесса.** Socket ограничен группой
   `mazzy-vpn`, но Bash dispatcher не получает `SO_PEERCRED`. Audit не содержит
   достоверный UID/PID caller. Нужен native daemon, проверяющий peer credentials
   и policy для каждой операции.
3. **Windows/macOS не поднимают туннель.** Сборка Tauri доказывает только
   компиляцию UI. Нет Windows Service/Wintun backend, Network Extension,
   platform secret storage, подписания, notarization и functional VPN tests.
4. **Android/iOS отсутствуют.** Нет Gradle/Xcode проектов, `VpnService` или
   Packet Tunnel provider, mobile signing, real-device tests и store metadata.
5. **Нет доверенной release chain.** Артефакты preview не подписаны. Нет SBOM,
   provenance/attestation, обязательной проверки подписей обновления и
   проверенного rollback. Checksums без защищённой подписи не подтверждают
   издателя.
6. **Нет clean-device/system integration gates.** Unit/regression tests
   используют fake environment. Не проверены реальные systemd socket
   permissions, upgrade/uninstall, route/DNS leak, crash во время операции,
   sleep/resume, смена сети и восстановление после reboot.

### P1 — должны быть закрыты до Linux Desktop 1.0

1. `deadline_ms` валидируется, но не является строгим end-to-end deadline:
   подготовка до mutation timer не учитывается, секунды округляются вверх.
2. После удаления старой idempotency record из ограниченного журнала очень
   старый `action_id` может выполниться снова. Нужен срок действия/tombstone
   protocol, явно согласованный с клиентами.
3. Если snapshot прерванного action отсутствует, записывается
   `rollback-failed`, но daemon не входит в обязательный recovery-only mode.
4. Новые API/client ошибки в основном захардкожены по-русски, хотя продукт
   заявляет шесть языков.
5. Desktop читает публичные status/profile caches для части query и переводит
   через API только lifecycle. Doctor, services, import, tests и modes ещё не
   мигрированы.
6. Status/profile caches имеют mode `0644`: любой локальный пользователь видит
   public IP, display names и имена файлов. Ужесточение прав потребует
   продуманной multi-user модели, а не только замены chmod.
7. Rust `Command::output()` сначала полностью накапливает stdout/stderr дочерней
   команды и только затем обрезает результат. Нужен streamed bounded capture с
   kill по deadline/лимиту.
8. Release workflow использует плавающие `macos-latest`, `windows-latest` и
   Rust `stable`. Воспроизводимость toolchain и runner image не зафиксирована.
9. Каталог `dist/` хранит старые бинарные артефакты; `SHA256SUMS` не включает
    `mazzy-vpn-1.0.0.tar.gz`. Источник истины для старых release files
    неоднозначен.

### P2 — качество и сопровождение

1. Нет fuzz/slowloris/soak тестов local API и длительного fault-injection.
2. Нет `cargo audit`/`cargo deny`, автоматического SBOM и подписи provenance.
   Lockfiles и Dependabot есть, но этого недостаточно.
3. Актуальный `npm audit` не выполнен в этом аудите: sandbox запретил отправлять
   dependency metadata во внешний registry без отдельного согласия.
4. API contract содержит 25 операций, но большинство transport handlers ещё
   отсутствует. Статус `partial` должен сохраняться до фактической реализации.
5. Man page, contextual help, redacted support bundle и cancellable progress
   для долгих операций не завершены.

## Как должны устанавливаться зависимости

Полностью автоматическая установка системных VPN-компонентов одной универсальной
командой невозможна и небезопасна. Нужны platform-native пакеты:

- **Linux:** DEB/RPM объявляют зависимости package manager; AppImage запускает
  отдельный подписанный, явно подтверждённый privileged bootstrap. Installer
  использует только pinned source commits и проверяет post-install состояние.
- **Windows:** signed MSIX/MSI/EXE ставит Windows Service и подписанный tunnel
  driver/backend через elevation. Приложение не скачивает произвольные
  исполняемые файлы при первом запуске.
- **macOS:** signed app bundle включает Network Extension. Установка проходит
  через системное разрешение extension; Developer ID build notarized и stapled.
- **Android:** backend библиотека входит в signed AAB/APK. Разрешение VPN
  выдаётся через системный `VpnService.prepare`; нативные `.so` собираются ABI
  matrix в Gradle.
- **iOS:** Packet Tunnel extension входит в signed archive с правильными
  entitlements/App Group. Зависимости встраиваются на этапе Xcode build; runtime
  installer запрещён моделью iOS.

## Обязательная архитектура по платформам

### Windows

- service под Service Control Manager с минимальным IPC и restrictive ACL;
- WireGuard/Wintun как первый backend, DPAPI/Credential Manager для секретов;
- signed/timestamped installer и все бинарные компоненты;
- install/upgrade/uninstall/rollback tests на чистых Windows VM;
- route, DNS, leak, crash, sleep/resume и network-change integration tests.

### macOS

- `NEPacketTunnelProvider`/Network Extension с Apple entitlement;
- App Group IPC и Keychain, без root shell adapter;
- hardened runtime, Developer ID signing, notarization и stapling;
- тесты на реальном Mac: extension approval, upgrade, sleep/wake, DNS/routes.

### Android

- native `VpnService`: consent, foreground notification, `Builder.establish`,
  `protect()` для tunnel sockets и корректный `onRevoke`;
- WireGuard engine, Android Keystore и Storage Access Framework;
- always-on/lockdown, Doze, reboot, network-change и upgrade tests;
- signed AAB, Play App Signing, актуальный target API и Data safety disclosure.

### iOS

- Packet Tunnel Network Extension, Keychain и App Group;
- Apple Developer organization account и VPN entitlements;
- on-demand lifecycle, network-change/background recovery;
- real-device tests, TestFlight, privacy manifest/disclosures, export compliance
  и App Review.

## Проверки аудита

Локально подтверждены:

- Bash syntax и ShellCheck;
- Rust format, Clippy с `-D warnings` и 10 unit tests;
- strict API contract: 25 операций и 14 error codes;
- capability registry: 14 capabilities и 6 release gates;
- SHA-256 для четырёх файлов, перечисленных в `dist/SHA256SUMS`;
- shell regression suite: 59/59;
- предыдущие GitHub checks обоих Draft PR были зелёными, но после новых
  commits обязателен новый CI.

Не проверено и не должно подразумеваться:

- реальное VPN-подключение на чистом Linux host;
- Windows/macOS VPN lifecycle;
- Android/iOS build или lifecycle;
- production signing, notarization, stores, upgrade/rollback;
- актуальный online `npm audit`.
