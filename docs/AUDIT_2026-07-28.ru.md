# Аудит Mazzy VPN — 2026-07-28

Copyright © 2026 [Nik m (@mazurovn)](https://github.com/mazurovn).

## Вердикт

Текущий `main` нельзя считать готовым к production-релизу Desktop или mobile.
Фактически опубликованный стабильный CLI/TUI — 1.2.0; 1.3.0 пока является
кандидатом в `main` после merge
[#30](https://github.com/mazurovn/mazzy-vpn/pull/30). Защищённый local API,
CLI/TUI client, package-owned lifecycle, location probes и egress diagnostics
уже слиты. Это устраняет прежний Draft-разрыв, но не закрывает перечисленные
ниже production gates.

Опубликован Linux Desktop 0.2.0 preview; 0.3.0 — кандидат. Windows и macOS
0.2.0 artifacts — неподписанные UI preview без VPN backend. Исходников
Android/iOS приложений в репозитории нет. Выпускать эти четыре платформы как
работающий VPN сейчас нельзя.

Аудит охватывает Bash engine/installer, systemd local API, CLI/TUI, Rust/Tauri
Desktop adapter, GitHub Actions, release artifacts, dependency chain,
capability registry и планы Windows, macOS, Android и iOS.

## Незакрытые технические риски

### P0 — блокируют production

1. **Нет общего native core/service.** `mazzy-vpn` — root-executed Bash-монолит
   более чем на 5 500 строк. Local API реализует только status, profiles и
   lifecycle на Linux; остальные Desktop операции продолжают использовать
   `pkexec`. Это не переносимая архитектура Windows/macOS/mobile.
2. **Нет идентификации вызывающего процесса.** Socket ограничен группой
   `mazzy-vpn`, но Bash dispatcher не получает `SO_PEERCRED`. Audit не содержит
   достоверный UID/PID caller. Нужен native daemon, проверяющий peer credentials
   и policy для каждой операции.
3. **Windows/macOS не поднимают туннель.** Сборка Tauri доказывает только
   компиляцию UI. Нет Windows Service/Wintun backend, Network Extension,
   platform secret storage, подписания, notarization и functional VPN tests.
4. **Android/iOS отсутствуют.** Нет Gradle/Xcode проектов, `VpnService` или
   Packet Tunnel provider, mobile signing, real-device tests и store metadata.
5. **Нет доверенной release chain.** Артефакты preview не подписаны. Нет SBOM,
   provenance/attestation, обязательной проверки подписей обновления и
   проверенного rollback. Checksums без защищённой подписи не подтверждают
   издателя.
6. **Нет clean-device/system integration gates.** Unit/regression tests
   используют fake environment. Не проверены реальные systemd socket
   permissions, upgrade/uninstall, route/DNS leak, crash во время операции,
   sleep/resume, смена сети и восстановление после reboot.

### P1 — должны быть закрыты до Linux Desktop 1.0

1. `deadline_ms` теперь вычитает mutation preflight из монотонного бюджета,
   сохраняет миллисекундную точность и не запускает executor после истечения.
   Но это всё ещё не строгий deadline всего request/response: чтение и
   envelope validation происходят до старта бюджета, а обязательные
   crash-reconciliation/rollback используют отдельный ограниченный completion
   grace. Общего безопасного cancel для всего service request пока нет.
2. После удаления старой idempotency record из ограниченного журнала очень
   старый `action_id` может выполниться снова. При текущем произвольном
   Identifier точная бесконечная история несовместима с bounded storage:
   нужен новый согласованный контракт с server-issued token/expiry или
   проверяемым issued-at, а не только увеличение retention.
3. Desktop читает отдельные group-restricted status/profile caches для части
   query и переводит через API только lifecycle. Doctor, services, import,
   tests и modes ещё не мигрированы; единая policy/data boundary отсутствует.
4. Compatibility child processes теперь имеют явные внешние deadlines,
   ограничение вывода и отдельное сообщение об indeterminate outcome после
   timeout мутации. Это всё ещё слабее local API: жёсткое завершение после
   начала изменения сети не даёт гарантированного reconciliation/action ID.
   Оставшиеся mutation paths нужно перенести в native service, а не считать
   timeout полным исправлением.
5. Полной воспроизводимости release build всё ещё нет: даже versioned GitHub
   runner labels получают обновления образов, Node задан только major-версией,
   а пакеты `apt` не закреплены. Rust 1.88.0 и поколения runner уже
   зафиксированы, но hermetic builder и сравнение бинарной воспроизводимости
   отсутствуют.
6. Dependency bootstrap остаётся частичным. DEB/RPM теперь устанавливают
   package-owned engine/service и обязательный base runtime; protocol packages
   объявлены recommendations, а явный `doctor --fix` остаётся для
   недоступных/AmneziaWG зависимостей. AppImage не может запустить embedded
   installer, если `pkexec` отсутствовал на host изначально.
7. Package lifecycle имеет идемпотентные install/upgrade/remove scripts и
   сохраняет `/etc/vpnctl`/`/var/lib/vpnctl`, но ещё нет clean-device VM matrix
   для всех дистрибутивов, fault injection postinst, package-manager rollback и
   проверки сложных legacy/custom unit overrides. Поэтому issue #4 и gate
   `desktop-linux-1.0` остаются открытыми.

### P2 — качество и сопровождение

1. Есть точечные fault-regressions для deadline и failed rollback, но нет
   fuzz/slowloris/soak тестов local API и длительного fault-injection.
2. `cargo-deny` RustSec advisory gate добавлен для Desktop Linux и падает на
   vulnerability, unsound и yanked advisories; текущий Tauri/GTK3 граф всё ещё
   блокируется `RUSTSEC-2024-0429`/`GHSA-wrw7-89jp-8q8g` в transitive
   `glib` 0.18. Повторная проверка crates.io 2026-07-30 подтвердила, что
   `tauri` 2.11.5 и `webkit2gtk` 2.0.2 уже являются текущими опубликованными
   версиями, а `cargo update --dry-run` не выводит граф из `glib` 0.18; нужен
   upstream migration/reviewed patch, а не обычный lockfile bump. Первый
   PR #32 RustSec run также нашёл исправимые `quick-xml`/`time` advisories;
   для них Desktop MSRV поднят до Rust 1.88, `plist` обновлён до 1.10.0,
   `quick-xml` — до 0.41.0, `time` — до 0.3.54.
   Автоматического SBOM и подписи provenance всё ещё нет.
3. `npm audit --audit-level=high` на 2026-07-28 сообщил 0 известных
   vulnerabilities. Это point-in-time registry check: он не покрывает Rust,
   системные packages, malicious maintainer update или будущие advisories.
4. API contract содержит 26 операций, но большинство transport handlers ещё
   отсутствует. Статус `partial` должен сохраняться до фактической реализации.
5. Man page, contextual help, redacted support bundle и cancellable progress
   для долгих операций не завершены.

## Как должны устанавливаться зависимости

Полностью автоматическая установка системных VPN-компонентов одной универсальной
командой невозможна и небезопасна. Нужны platform-native пакеты:

- **Linux:** DEB/RPM объявляют зависимости package manager; AppImage запускает
  отдельный подписанный, явно подтверждённый privileged bootstrap. Installer
  использует только pinned source commits и проверяет post-install состояние.
- **Windows:** signed MSIX/MSI/EXE ставит Windows Service и подписанный tunnel
  driver/backend через elevation. Приложение не скачивает произвольные
  исполняемые файлы при первом запуске.
- **macOS:** signed app bundle включает Network Extension. Установка проходит
  через системное разрешение extension; Developer ID build notarized и stapled.
- **Android:** backend библиотека входит в signed AAB/APK. Разрешение VPN
  выдаётся через системный `VpnService.prepare`; нативные `.so` собираются ABI
  matrix в Gradle.
- **iOS:** Packet Tunnel extension входит в signed archive с правильными
  entitlements/App Group. Зависимости встраиваются на этапе Xcode build; runtime
  installer запрещён моделью iOS.

## Обязательная архитектура по платформам

### Windows

- service под Service Control Manager с минимальным IPC и restrictive ACL;
- WireGuard/Wintun как первый backend, DPAPI/Credential Manager для секретов;
- signed/timestamped installer и все бинарные компоненты;
- install/upgrade/uninstall/rollback tests на чистых Windows VM;
- route, DNS, leak, crash, sleep/resume и network-change integration tests.

### macOS

- `NEPacketTunnelProvider`/Network Extension с Apple entitlement;
- App Group IPC и Keychain, без root shell adapter;
- hardened runtime, Developer ID signing, notarization и stapling;
- тесты на реальном Mac: extension approval, upgrade, sleep/wake, DNS/routes.

### Android

- native `VpnService`: consent, foreground notification, `Builder.establish`,
  `protect()` для tunnel sockets и корректный `onRevoke`;
- WireGuard engine, Android Keystore и Storage Access Framework;
- always-on/lockdown, Doze, reboot, network-change и upgrade tests;
- signed AAB, Play App Signing, актуальный target API и Data safety disclosure.

### iOS

- Packet Tunnel Network Extension, Keychain и App Group;
- Apple Developer organization account и VPN entitlements;
- on-demand lifecycle, network-change/background recovery;
- real-device tests, TestFlight, privacy manifest/disclosures, export compliance
  и App Review.

| высокая | ICMP timeout смешивался с недоступностью VPN; latency вообще не измерялся | Для каждого профиля отдельно передаются `reachable`, `unknown`, `unreachable`, `invalid`, `active`, ICMP/TCP latency и source. UDP с DNS без ICMP — `unknown`; только live-test доказывает credentials/handshake/routes |
| высокая | Последовательный `probe all` мог занимать `profiles × timeout`; 32 socket clients могли параллельно умножить нагрузку | Внутри batch разрешены 1–8 workers, каждый DNS/ICMP/TCP шаг bounded, весь query ограничен deadline, а batch requests сериализованы глобальным `flock`. Progress/cancellation и rate policy для будущего native daemon остаются открыты |
| средняя | Desktop не связывал результат проверки со строками локаций | Экран Profiles показывает отдельный статус, latency и текущий active tunnel для каждого opaque profile ID; есть «Проверить все локации» и protocol scope |
| средняя | `app.css` участвовал в бинарной UI-сборке, но отсутствовал в явном package-owned corresponding-source payload | CSS добавлен в DEB/RPM source tree и AppImage embedded source; assembled package audit проверяет его наличие |
| высокая | RPM сохранял mode исходного script из checkout: при builder `umask 0002` `/usr/bin/mazzy-vpn` становился `0775`, хотя DEB был `0755` | Release builder временно нормализует все runtime executables в `0755`, после build восстанавливает локальные modes; fresh assembled DEB/RPM/AppImage audit проходит |

Эта функция измеряет доступность endpoint, а не «работает ли VPN» в полном
смысле. Она не меняет маршруты и безопасна для массового запуска. Для
доказательства авторизации, handshake, DNS и маршрутизации сохраняется отдельный
транзакционный `test`/`test-all` с rollback. Windows/macOS и Android/iOS смогут
использовать тот же result contract, но до native backend и platform transport
их поддержка остаётся `planned`.

## Аудит фактического egress и «локация выбрана, но VPN не работает»

Новый `verify` закрывает часть разрыва между выбранным названием профиля и
наблюдаемой сетью, но не превращает геолокацию IP в абсолютное доказательство:

| Важность | Риск | Текущее поведение и ограничение |
|---|---|---|
| высокая | GUI показывает выбранный профиль, хотя default traffic выходит иначе | Сравниваются IPv4, привязанный к VPN-интерфейсу, и IPv4 default egress; расхождение всегда `warning` |
| высокая | Geo provider может ответить про другой IP | Ответ исключается, если его IP не равен interface-bound IPv4; два допустимых provider должны быть разными и согласовать страну |
| высокая | Один внешний источник создаёт ложную уверенность | Один provider даёт `warning`; `verified` требует два согласованных ответа |
| высокая | IPv6 выходит мимо IPv4-only tunnel | Наличие другого default IPv6 помечается как потенциальная утечка; это signal, а не packet-capture доказательство |
| средняя | `~.` виден на VPN link, но фактический resolver path сложнее | Проверяется конфигурация `systemd-resolved`; это не полноценный DNS leak test через authoritative domain |
| средняя | В профиле нет явного `mazzy-country-code` | Фактическая страна показывается, но итог остаётся `warning` и `country_match=unknown`; имя файла, display name и город не используются как источник ожидаемой страны |
| средняя | Speed test создаёт трафик и может влиять на рабочую сессию | Только явный `--speed`/кнопка; bounded download 5 MB через tunnel interface, в monitor не запускается |
| высокая | AI/video session может ломаться при loss/jitter, хотя IP и DNS верны | Текущий verify этого не измеряет. Нужны отдельные active quality metrics, безопасные thresholds и application-level probes без заявлений о доступности конкретного сервиса |

`verified` означает согласованные наблюдаемые network signals в момент проверки,
а не гарантию доступа к конкретному AI provider, видео-платформе или
корпоративному порталу. Account region, cookies, WebRTC, device location,
organization policy и provider-side risk scoring остаются вне контроля клиента.
